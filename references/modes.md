# Modes

## Mode Selection

- `intake`
  - 用在信息不够、卦例还没成形、用户先要检查“能不能断”。
  - 目标不是解卦，而是补齐输入契约。

- `quick-reading`
  - 用在用户要一个快而准的结论，不要全流程展开。
  - 只保留结论、主因、风险点、下一步。

- `full-reading`
  - 用在用户明确要求完整断卦、实战清单、逐步展开。
  - 必须按九步输出，不要跳步。

- `review`
  - 用在用户已经给了自己的断语，想知道哪里逻辑不稳、哪里体系混乱、哪里证据不足。
  - 重点不是重新从零写一篇，而是指出原断语的断点。

## Mode Rules

### intake
- 只问最小必要字段：
- 问什么
- 本卦或上下卦
- 动爻或是否无动
- 若涉及旺衰难分，再补月令或日辰
- 若用户只给“某卦变某卦”，不要立刻要求所有细节都齐全。
- 输出里把信息分成：
- 已有，可直接用
- 缺失，但必须补
- 缺失，但可先不补

### quick-reading
- 压缩成一屏能读完的输出。
- 仍要隐含主轴，不要直接玄断。
- 至少交代：
- 体用关系
- 旺衰倾向
- 动爻变化起点
- 变卦落点

### full-reading
- 按九步逐条展开。
- 每一步都要明确“这一步回答了什么问题”。
- 最终一定要翻译成人话，不要停在术语层。

### review
- 先摘出原断语里的主判断。
- 再按下面四类检查：
- 体用是否定错
- 关系与力度是否混淆
- 辅助层是否喧宾夺主
- 结论是否过满
- 输出要像 code review：先给核心问题，再给修改建议。

## Depth Control

- 如果用户是初学者，解释时多写因果链，少写黑箱结论。
- 如果用户是复盘高手，优先指出口径冲突和判断强弱，而不是重复基础概念。
- 如果用户一次给很多卦例，不要全部 full-reading；先建议改走 `intake -> quick-reading -> 挑重点 full-reading`。
